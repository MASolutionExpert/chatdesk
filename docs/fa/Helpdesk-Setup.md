# هِلپ‌دسک (دپارتمان‌ها و اپراتورها)

سونگبرد می‌تواند به‌صورت یک **هِلپ‌دسک چت‌محور** کار کند: تجربه‌ی کاربر مثل یک
مسنجر معمولی است، اما پشت‌صحنه هر گفتگوی پشتیبانی به تیم درست مسیریابی می‌شود.

## نحوه کار

1. **سوپر ادمین دپارتمان‌ها را می‌سازد** در پنل مدیریت (تب `Helpdesk` →
   `New department`)؛ مثلاً *پشتیبانی فنی* یا *مالی*.
2. **سوپر ادمین اپراتورها را می‌سازد** در تب `Users` (`New user` → نوع اکانت
   `Operator` → دپارتمان). اپراتورها مثل کاربر عادی وارد می‌شوند و صندوق
   ورودی‌شان همان لیست چت‌های معمولی است.
3. **مشتری دپارتمان را انتخاب می‌کند** بلافاصله بعد از ثبت‌نام (صفحه
   `/departments`) یا هر زمان دیگر از منوی سایدبار (`+` → `Contact support`).
4. **مسیریابی عادلانه** گفتگو را به اپراتوری از آن دپارتمان می‌دهد که
   *کمترین گفتگوی باز* را دارد (باز = آخرین پیام از طرف مشتری است). در حالت
   تساوی، نوبت‌دهی گردشی اعمال می‌شود (کسی که دیرترین زمان تخصیص را دارد).
5. گفتگوی پشتیبانی یک **چت DM معمولی** است که با دپارتمان تگ شده، پس همه‌ی
   قابلیت‌های مسنجر سر جایشان هستند: فایل، ویس، تماس، نوتیفیکیشن، صف آفلاین
   و رمزنگاری.
6. اگر مشتری دوباره به پشتیبانی پیام بدهد، سرور همان DM قبلی با همان اپراتور
   را ادامه می‌دهد (یا به اپراتور دیگری مسیریابی می‌کند)، بنابراین گفتگوها
   مثل مسنجر باقی می‌مانند.

## اکانت‌های اپراتور

اپراتورها اکانت‌های عادی با نقش `operator` هستند:

- فقط توسط owner/admin ساخته می‌شوند (تب `Users` → `New user` → نوع اکانت
  `Operator`) یا از طریق CLI:
  ```bash
  npm run db:user:create -- --nickname "Sara Ahmadi" --username sara \
    --password "..." --role operator
  ```
- مقدار مجاز نقش در CLI: `user | operator | admin | owner`
- اپراتورها **دسترسی به پنل مدیریت ندارند**.
- دپارتمان کاربر هر زمان از طریق `PATCH /api/admin/users/:id` با
  `{ "department_id": <id> }` قابل تغییر است (یا از رابط پنل مدیریت).
  ویرایش دپارتمان‌ها در تب `Helpdesk` انجام می‌شود.

## API ادمین

| متد | اندپوینت | کاربرد |
| --- | --- | --- |
| `GET` | `/api/departments` | دپارتمان‌های فعال (کاربران وارد‌شده) |
| `POST` | `/api/support/request` | ساخت/ادامه گفتگوی پشتیبانی با مسیریابی عادلانه |
| `GET` | `/api/admin/departments` | همه دپارتمان‌ها + اپراتورهای هر دپارتمان |
| `POST` | `/api/admin/departments` | ساخت دپارتمان `{ name, description, color }` |
| `PATCH` | `/api/admin/departments/:id` | ویرایش / فعال / غیرفعال |
| `DELETE` | `/api/admin/departments/:id` | حذف نرم (غیرفعال‌سازی، حفظ تاریخچه) |
| `GET` | `/api/admin/support/overview` | گزارش هر دپارتمان + آخرین گفتگوها |

## گزارش‌ها

تب `Helpdesk` در پنل مدیریت برای هر دپارتمان نشان می‌دهد:

- تعداد کل گفتگوها، گفتگوهای باز، تعداد کل پیام‌ها
- اپراتورهای آماده به کار
- آخرین گفتگوهای پشتیبانی با وضعیتشان
  (`awaiting reply` = آخرین پیام از مشتری است)

## دیتابیس

دپارتمان‌ها با مایگریشن `042-departments` ساخته می‌شوند:

- جدول `departments`
- ستون `users.department_id` (اپراتورها)
- ستون `chats.department_id` (گفتگوهای پشتیبانی)

اجرای آن هنگام بوت سرور به‌صورت خودکار برای SQLite و PostgreSQL انجام می‌شود
و در بکاپ‌های دیتابیس هم لحاظ می‌شود.
